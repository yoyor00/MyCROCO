# SCons backend for CROCO

This package implements the optional SCons compilation backend of
`OCEAN/jobcomp.py`.  It is based on the standalone `SCONS/scons` example and
keeps its dependency scanners, compile passes and SCons build steps.

## Usage

From a prepared CROCO run directory:

```bash
./jobcomp --scons --jobs 8
```

or persist the choice:

```bash
# command line
CROCO_BUILDER=scons ./jobcomp --jobs 8

# jobcomp.conf
BUILDER=scons
```

The default backend remains `make`; `--sh` is unchanged.

`jobcomp` prepares `Compile/`, writes `Compile/croco_build.json`, builds the
AGRIF library and then invokes:

```bash
scons -f <OCEAN/python/scons/SConstruct> -j 8 croco partit ncjoin
```

The `SConstruct` reads `Compile/croco_build.json`.  It can also be invoked
manually from `Compile/`:

```bash
cd Compile
CROCO_SCONS_PACKAGE=/path/to/OCEAN/python \
    scons -f /path/to/OCEAN/python/scons/SConstruct -j 8 croco partit ncjoin
```

## Installation

SCons is optional and only required for `--backend scons`:

```bash
python3 -m pip install -r OCEAN/python/scons/requirements.txt
```

If SCons is missing, `jobcomp --backend scons` reports an explicit error;
normal `make` builds are unaffected.  `--dry-run --scons` prints the command
without requiring SCons.

## Contents

```text
SConstruct                  SCons entry point used by jobcomp
backend.py                  command/availability helpers for jobcomp
config.py                   typed reader for croco_build.json
croco_env.py                builds the SCons environment from the manifest
croco_build.py              preprocess/compile/link primitives
croco_bin.py                default CROCO executable pipeline
croco_tools.py              mpc, check tools, partit, ncjoin, ncrename
deps/                       preprocessor and Fortran dependency scanners
compile_passes/             cpp/mpc/change_loops stages
```

## Input manifest

`Compile/croco_build.json` is generated by `jobcomp` and contains the resolved
toolchain, flags, feature switches, source lists and the selected OS
environment.  SCons does not parse `Makedefs` or `Makefile` again.

## Known limitations

- AGRIF source conversion is not implemented in the SCons backend yet.  Use
  the make backend for AGRIF builds; SCons raises an explicit error when the
  manifest reports `features.agrif: true`.
- The dependency scanners follow preprocessor includes from the original
  source file.  Dependencies introduced only by a source-to-source pass are
  not tracked.

## Not included

MULE-specific compile passes and Tapenade/autodiff modules are not part of this
package.  They depend on external projects and source files that are not part
of the current CROCO tree.
